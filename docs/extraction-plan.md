## Bounded dependency closure

1. Provider-neutral selected geographic values and local civil input adapters. Advisory search is
   separate and not necessary for deterministic requests. No GeoNames dependency in this scaffold.
2. Offline pinned TBB boundary resolver and explicit unique/boundary/ambiguous/no-match fact types.
3. Historical civil-time resolver using pinned compiled tzdb/TZif, explicit fold choice/gap failure.
4. Isolated Swiss worker, UTC/time-scale conversion, exact native flags and raw ephemeris ports;
   preserve process/global-state controls, no fallback, binary64/decimal representations and limits.
5. Only raw Sun/Moon fact assembly and newly authored single-person orchestration. Do not copy an
   existing combined compatibility calculation orchestrator and attempt to strip private fields.
6. Public AstroPassport serializer/provenance after exact contract/profile/comparator approval.

No synastry, scoring, relationship roles, ParticipantContext, social/account logic, identity keys,
interpretation, UI, database, private provider configuration or complete identity machinery moves.
APT is the future sole Swiss-containing service; this checkpoint does not make that migration true.
ACE consumes authenticated HTTP as any external client; no shared imports, database or special route.
Unbubble social/account services stay separate from ACE's calculation/business-methodology domain.

1. Bootstrap/API candidate and plan: local gates, exact-head CI, independent licensing/security audit.
2. AAC approves detailed wire semantics/publication bytes/licence, comparator leaves, complete ACEP1
   profile/vectors where required. Limited Sun/Moon output never claims full NCF/NAD or ACEP1.
3. Author independent public synthetic fixtures; privately retain old runtime/corpus evidence.
4. Extract narrowly with public source/notice inventory, exact-head CI and mandatory scientific,

5. Human approves ACE cutover separately. Then client-only release must preserve downstream parity,
   explicit errors, no fallback and unchanged private methodology. A separate approved ACE ADR must
   supersede any conflicting current ACE ownership/licensing decision; AAC does not silently do so.

Before cutover, retain the unchanged accepted old service. After cutover, rollback only to compatible

into proprietary ACE, downgrade schemas, recompute provenance with newer data or mask failure with
another provider. API/profile incompatibility fails unavailable. Public launch/deployment is separate.
